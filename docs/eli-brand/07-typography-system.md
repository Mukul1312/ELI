# Typography System

Eli uses a **bimodal typography system** because the product needs to do two different jobs at once:

- feel human enough to be trusted
- stay clear enough to be usable under pressure

Typography should express that duality without becoming ornate, branded-for-its-own-sake, or visually busy.

## Why Eli Needs Typographic Duality
A single typographic voice would make Eli feel either too mechanical or too stylized. The system therefore separates:

- **Voice Type:** the layer that carries Eli's presence
- **Structure Type:** the layer that carries tasks, controls, and orientation

This distinction allows the interface to stay practical while giving Eli a recognizable tone of presence.

## Type Roles

### 1. Voice Type
Voice Type appears when Eli is speaking, reflecting, or setting emotional tone.

Its job is to feel:
- human
- composed
- grounded
- slightly slower than utility text

Voice Type should not feel:
- loud
- decorative
- literary for its own sake
- luxurious in a way that distracts from the product

#### Behavior rules
- Use it sparingly, only where Eli's presence actually matters.
- Favor regular or book-like weights over assertive heaviness.
- Let spacing and rhythm create emphasis before boldness does.
- Use italics only as a rare modulation, not as the default emotional cue.

### 2. Structure Type
Structure Type appears wherever the interface needs to orient, label, or organize action.

Its job is to feel:
- clear
- calm
- trustworthy
- low-friction

Structure Type should not feel:
- overly branded
- overly technical
- compressed or urgent
- command-like

#### Behavior rules
- Use it for controls, labels, lists, metadata, and utility surfaces.
- Favor sentence case throughout the product.
- Use weight carefully: enough to guide the eye, not enough to create pressure.
- Default to legibility and stability over personality.

## Emphasis Behavior
Typography should create calm hierarchy, not theatrical contrast.

### What emphasis should feel like
- clearer
- steadier
- more intentional
- easier to follow

### What emphasis should not feel like
- louder
- more branded
- more urgent
- more emotionally manipulative

## Hierarchy of Calm
When type is assembled well, the student should feel the following order naturally:

1. **Presence:** Eli's voice is noticed first when emotional meaning matters.
2. **Action:** The next practical step is easy to locate.
3. **Support:** Labels, metadata, and secondary information stay available without competing.

The hierarchy should reduce cognitive load, not perform visual drama.

## Selection Criteria
Specific font choices are intentionally left open until tested, but any selected pair must satisfy these criteria:

### Voice Type must
- remain legible at mobile sizes
- feel human without becoming ornamental
- hold reflective or welcoming language without sounding theatrical
- pair cleanly with the structure type

### Structure Type must
- stay highly readable across controls and dense UI moments
- feel stable and contemporary without leaning “startup default”
- support calm hierarchy in sentence case
- coexist with the voice type without visual argument

## Design Constraint
Typography is one of Eli's main regulatory tools. If the system feels too expressive, it adds pressure. If it feels too neutral, Eli disappears. The correct balance is **present, calm, and usable**.

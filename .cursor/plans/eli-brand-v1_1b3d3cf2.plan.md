# Eli Brand System V1 Plan

## Goal

Create a new brand system in [docs/eli-brand](docs/eli-brand) that stands on its own, independent of older UX assumptions. The new docs should define Eli as a stable companion identity with adaptive expression, not a persona-specific brand.

## Scope

The work will create a clean documentation set for:

- Brand thesis and first-principles positioning
- Core identity constants that should not change across students
- Adaptive expression rules that vary by state and relationship maturity
- Brand states and brand phases
- Visual system, typography system, and voice/copy system
- Logo and asset usage rules
- Product UI principles that translate the brand into interface behavior
- Open questions and unresolved design decisions

## Content Direction

The new brand system will be written from scratch around these agreed foundations:

- Eli is a calm study companion that adjusts how it shows up without changing who it is.
- The brand is designed for student moments and capacity states, not fixed persona labels.
- The system has two layers: core brand constants and adaptive expression rules.
- Adaptation should regulate emotional and cognitive load rather than feel like cosmetic personalization.
- The product should feel safe, grounded, and specific; never gamified, clinical, or performatively motivational.

## Documentation Model

### 1. Thesis and identity

Write the foundational docs first:

- [docs/eli-brand/01-brand-thesis.md](docs/eli-brand/01-brand-thesis.md)
- [docs/eli-brand/02-core-identity.md](docs/eli-brand/02-core-identity.md)

These will define:

- What Eli is
- What Eli is not
- The emotional promise of the brand
- The permanent identity traits, non-negotiables, and anti-patterns

### 2. Adaptive system

Then define the adaptive model:

- [docs/eli-brand/03-adaptive-expression.md](docs/eli-brand/03-adaptive-expression.md)
- [docs/eli-brand/04-brand-states.md](docs/eli-brand/04-brand-states.md)
- [docs/eli-brand/05-brand-phases.md](docs/eli-brand/05-brand-phases.md)

These will establish:

- Core identity vs adaptive expression
- Brand states such as fragile, steady, ready, and reflective
- Relationship maturity phases such as universal calm, responsive companion, and earned familiarity
- Which levers can adapt: density, warmth, contrast, voice posture, specificity, and CTA energy

### 3. Design system translation

After that, formalize the design language:

- [docs/eli-brand/06-visual-system.md](docs/eli-brand/06-visual-system.md)
- [docs/eli-brand/07-typography-system.md](docs/eli-brand/07-typography-system.md)
- [docs/eli-brand/08-voice-and-copy.md](docs/eli-brand/08-voice-and-copy.md)

These will define:

- Semantic color roles like paper, ink, clay/terracotta, and green
- Rules for calm surfaces, spatial rhythm, and restrained motion
- A bimodal type system with Eli Voice and Structural Voice
- Tone rules, banned patterns, and example copy for low-capacity, steady, and reflective moments

### 4. Assets and product behavior

Then document brand usage in practical terms:

- [docs/eli-brand/09-logo-and-asset-system.md](docs/eli-brand/09-logo-and-asset-system.md)
- [docs/eli-brand/10-product-ui-principles.md](docs/eli-brand/10-product-ui-principles.md)

These will define:

- The role of the `ei` mark and full wordmark
- Rules for icon/app/favicons and signature-level logo presence
- Product UI laws such as one calm focal point, green is earned, terracotta invites, and no dashboard-style pressure surfaces

### 5. Index and decisions log

Finally:

- [docs/eli-brand/00-index.md](docs/eli-brand/00-index.md)
- [docs/eli-brand/11-open-questions-and-decisions.md](docs/eli-brand/11-open-questions-and-decisions.md)

The index will make the system navigable. The decisions log will capture unresolved choices like final font pairing, exact CTA accent, and small-size logo behavior.

## Implementation Sequence

1. Create the new folder and all target markdown files.
2. Draft the core thesis and identity docs first so the rest inherits a coherent voice.
3. Draft adaptive expression, states, and phases next so the system is structured around responsiveness rather than persona labels.
4. Translate that framework into visual, typography, and copy rules.
5. Finish with logo guidance, UI principles, index, and open questions.
6. Review the full set for consistency of tone, naming, and overlap between files.

## Deliverable Quality Bar

The finished docs should:

- Read as a clean v1 system, not an edit of legacy material
- Be specific enough for future product, brand, and UI decisions
- Avoid overfitting to current archetypes while still supporting adaptive design
- Keep the distinction between permanent brand identity and adaptive expression explicit in every relevant file

## Key Principle

The new system should make one idea unmistakable:

`Eli has one identity, many expressions.`
